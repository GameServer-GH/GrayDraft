# GrayDraft 设计理念

> **日期**：2026-10-29  
> 本文约束产品取舍：谁来操作，质量靠什么守住。端到端实现见 [系统逻辑总览](系统逻辑总览.md)。文末列出与当前代码不一致的地方，那些地方以本文为准改产品路径。

GrayDraft 以 AI 为操作主体。人把教程、论文、接口说明、课件和截图放进自己的工作区，提出问题，并遵守少量约定。查找、降噪、能否入库、能否作答、结论要不要写回去，由系统完成。主题会换成菜谱、药物或其它领域时，换的是资料与一句背景，不是再分叉一套专用流水线。

人的操作要少，并且尽量一次做完。每篇材料、每次提问、每条笔记都要人再点一次确认，工作台就会变成审核台。逐条审核可以让单条知识看起来更真，同时把处理成本抬到人无法持续的程度。本项目不采用这条路径。针对某一类样例专项刷分、却把其它领域甩远的优化，同样不采用。

## 最大程度减少人工操作，依赖 Agent 思考决策去进行闭环

Agent 在已授权的范围内完成判断、执行、复核、修正与验收。可确定计算的部分交给程序复算，需要理解语义的部分交给 Agent 依据可见证据判断。成文和复核共享同一证据包。失败时由 Agent 在预算内尝试修正并重新验收，保留首次失败、决策依据与最终结果。校准优先使用可独立判分的样例、规则验证和自动回归。

凡是必须由人工参与才能完成的环节，明确标记为**项目技术不可触达领域**。记录具体缺少的证据、权限或无法从系统输入推断的意图，以及受影响的结论或动作。系统继续完成可验证的部分，对其余部分给出范围受限的结果或终止本次动作。这个标记是闭环的终止状态，产品验收以自动完成或明确触达边界为准，流程禁止依赖人工标注、裁决、审批或接管才能继续。

## 质量靠两条守住

**技术把门。** 信息密度、去重、标题与实体是否回到原文、多模态识别质量、检索分级、作答门禁、引用约束。过不了门的内容不入库、不当作答案、不写回笔记。暂时做不到完美时，把降噪和拒收做到当前技术允许的最大限度，而不是改成人工抽查。

**约定守边界。** 使用者不把明知无效的材料放进工作区。这是使用方式，发生在导入之前，不是导入之后的审核表。

管理后台里的工具审批、死信重放、成本和离线评估，留给运行这套系统的人。它们可以事后抽看，不能成为一篇笔记或一份材料被下次提问找到的前置条件。

## 笔记写回

一次讲解里值得留下的结论，由 `note.draft` 写成笔记，走和原始材料相同的入库过程，并连回问题与原文切片。门禁通过后直接进入索引；索引完成后才能被下一次提问找到。

真实性由自动条件保证：

- 正文能指回本次检索到的原文切片，不靠摘要或关系代替引用
- 与作答相同的可信度门禁通过；证据不足就不写
- 只写当前被授权的工作区
- 入库后再经过质量门、去重和索引
- 门禁不通过时，这次运行说明没有留下笔记，不生成待人处理的单据

人不逐条放行。若某条笔记不该留，用已有的删除把它从工作区拿掉。

管理后台可以留下调用审计，供事后查看参数与结果。审计不是发布开关。

## 噪音与无效材料

噪音不靠人在预览里逐段勾选，也不靠人在后台把文档标成有效。

系统侧持续加强自动处理：低信息密度段丢掉，相同内容不重复写入，同标题内容变化则更新版本，标题不像正文则拒绝，实体无法回到原文则降级或丢弃，多模态识别质量不及格则不复用缓存并重新处理或放弃该附件，置信度低于阈值则不提交入库。拆分不确定时，收成系统能确定的段落，或丢掉不确定的段。不把行号范围交给人改。

人侧只保留一条约定：不要导入已知无效的文档。低置信度可以记在运行日志里，不因此弹出确认框。

近重复同样自动处理。哈希相同视为未变化；实体与标题规则能判定为同一篇则更新；判定不了则按新材料放入。不要求人在界面上选择合并哪一篇。

## 同类取舍

下面这些位置容易滑成「每来一条，人处理一次」。产品路径一律走自动门禁或事先约定。

| 位置 | 不采用的人为工序 | 采用的做法 |
|------|------------------|------------|
| 笔记发布 | 管理后台逐条审批后才可检索 | 引用与作答门禁通过后自动入库 |
| 噪音文档 | 导入预览里逐段确认、勾选有效段 | 降噪与阈值自动丢弃；约定不导入无效材料 |
| 切分边界 | 人拖动或修改 `segments_override` | 自动拆分；不确定则收束或丢弃该段 |
| 近重复 | 警告后让人选保留哪篇 | 哈希与实体规则自动判定未变化、更新或新放入 |
| 答案能否发出 | 人点头后才展示 | 作答门禁自动放行，或替换为说明范围内没有依据的回复 |
| 逐句来源 | 人核对每一句再发送 | 系统自动标注来源与覆盖程度，直接展示。展示是告知，不是审批 |
| 长期记忆 | 每写一条弹窗征求同意 | 只在当前工作区自动记录；敏感内容默认不记；过期自动清理。人要清，用整库清理 |
| 记忆冲突 | 人裁定哪一条为准 | 系统按版本与时间保留可解释的一条，旧条退出召回 |
| 赞与踩 | 必须反馈，系统才继续工作 | 可选信号，自动进入质量统计。没有反馈时检索与作答照常进行 |
| 工具执行 | 每次调用前向人确认 | 只读查找直接执行。写笔记走上面的自动门禁 |
| 向人追问 | 稍有不确定就反问 | 能换查法就继续查。只有缺了无法从资料中代替的对象时，才问一句 |
| 查法选择 | 人指定词法、语义或扩展 | Agent 按问题选择查找工具，同一种查法不对同一问题重复做 |
| 材料互相矛盾 | 人开单裁定哪份对 | 回答里并列引用，并说明资料之间不一致 |
| 入库失败 | 人在后台逐条重放，学习路径才算完成 | 自动重试。重试耗尽进入死信，供运行系统的人处理，不挡在提问前面 |
| 工作区背景 | 填完长表才能开始用 | 一句话说明这份资料是什么即可，其余字段由系统补全。之后可改，不是每问一次的操作 |
| 模型与提示 | 每个问题重新调参 | 默认模型与策略固定。工作区补充提示是可选约定，写一次生效 |
| 课件与截图 | 人核对识别文本后才入库 | 识别、缓存与质量分自动完成；不及格不入库 |
| 对话里的媒体 | 人先描述图里有什么 | 图片、视频、链接先转成文字，再进入同一次提问或导入 |

展示依据、导出原文、断线后从上次位置继续、失败后重试同一次任务，仍然要做。它们把系统已经做出的结果交给人使用，不增加审核工序。

筛选、相关阅读、记忆列表同理：接上是为了查找和撤回已有结果。记忆列表如果做成「每条点同意才生效」，就违反本文。

## 人仍然要做的事

- 决定把哪份材料放进工作区，并遵守不导入已知无效文档的约定
- 提出问题
- 一次性设置：工作区钥匙、一句背景、可选的补充提示
- 明确的破坏性操作：删除条目或整库、切换工作区、清空缓存。这些动作的意图无法从材料里推断
- 运行系统的人查看健康、死信、成本和抽样评估。抽样用来改进门禁，不用来逐条放行

## 判断一个新功能时

加按钮、加确认框或加审批页之前，按这个顺序看：

1. 这件事能否由门禁、降噪、检索或策略自动完成？能，就自动完成。
2. 不能自动完成时，它是一次性约定，还是会随着每篇材料、每次提问重复出现？
3. 会重复出现的人为确认，默认不做。质量用技术补，边界用约定守。
4. 若只是把已有结果给人看、给人拿走、给人从中断处继续，可以做，并且不要在前面再加一道批准。
5. 这项改动是在修一类材料上的通用机制（协议、门禁、计划、分段），还是只在贴合当前样例集？只贴合样例集的，默认不做（见下一节）。

## 局部最优要导向全局最优

工作区会换材料：技能说明、论文、菜谱、药物说明书、课件，主题会变，题型结构往往仍是专名、参数、步骤、跨段对照、材料外拒答。优化针对的是这些**结构**，不是某一个垂类词表或某一场赛事的题面。

**不以专项过度优化换单域分数。** 为 SCP 工具名、为某篇 arXiv 数字、为某一味药名去加专用分支、专用提示或专用路由，可以抬高当前集，同时把系统钉死在该域。下一份菜谱或药物工作区进来时，要么无效，要么互相打架。这类改动默认不做。

**局部改动要能抬高一类材料，而不是只抬高这一份材料。** 例如：加固规划 JSON、证据够禁止空澄清、首跳按意图固定查法、长文自动分段、跨文档用文档组而不是扁平切片——这些对说明类、论文类、菜谱类、药物类应同向受益。若一项优化在 SCP 上升、在论文下降，或预期在新域无效，就还没到可合并的形态。

**领域差异交给工作区约定与蓝图，不写进热路径硬编码。** 一句工作区背景、可选补充提示、按工作区进化的语义蓝图，用来吸收「这份资料是什么」。热路径上的分类器、工具、门禁、成文策略保持领域无关；换域时改的是资料与背景，不是再分叉一套 Agent。

判断一项优化是否可做时，多问一句：去掉当前样例专名之后，它是否仍说得通？下一份完全不同主题的工作区，是否大概率同步变好，而不是大致不变或变差？后者才进入实现。

赛事集与回归集用来验收，不用来定义产品形状。通过 SCP / 论文复测是必要的；再增加菜谱、药物等样例时，同一套机制应能直接跑，而不是先开专项分支。

## 账号与授权

隔离单位是工作区钥匙。工作台不做使用者账号，也不做「把这一区授给谁」。单人使用时钥匙已经够用。要给多人共用同一批资料时，再增加账号和授权对象。在那之前，不把登录和角色做成功能点缀。

## 与当前实现的差距

下列行为仍在代码或学习文档里，产品方向以本文为准。

| 现状 | 应改成 |
|------|--------|
| 智能导入置信度低于阈值时返回预览，调用方仍可能据此再提交 | 低于阈值则不入库。不为此做确认界面 |
| 学习文档中「笔记审批后再入库」的表述 | 改成「带引用的笔记直接入库」 |

笔记写入已固定为带引用后直接入库，租户工具表不能把它改回审批。长期记忆不再要求逐条同意；设置里可以查看并撤回。对话记录写入服务端线程，本机只留副本。引用按切片返回，并带上课件媒体地址；详情里展示该页的识别文字。原图本身没有入库，所以这里展示的是识别结果。

作答门禁、检索分级、导入去重、质量门和工作区隔离保持为自动路径，不要在它们前面再加人审。
