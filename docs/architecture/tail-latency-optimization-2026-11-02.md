# 总览尾延迟优化与验证（2026-11-02）

## 1. 问题与结论边界

上一轮完整回归 `20261102T082010568129Z_full.json` 的 `paper-theme` 端到端约 32.5 秒。逐篇并发使整题等待最慢分支；曾出现一个分支约 32.3 秒，另外两篇约 3–4 秒。后续慢样本既包含等待首正文，也包含持续缓慢生成，单纯治理首 token 或空闲时间不足。

已证实：开发环境中的复杂模型概述延迟波动大；直接换快层会漏掉图注中的完整型号，增加提示或一次纠正仍不稳定。上游排队、负载或推理服务内部原因没有证据，不作归因。一次普通问答明确收到上游 `-20048`（请求过于频繁），该次失败与概述选层分开记录。

## 2. 最终保留的实现

- **保守选层**：新增 `chat.overview_model: fast|complex`，默认 `complex`，开发配置显式启用 `fast`。只有没有必保参数规模型号的短概述使用配置层；有必保型号的概述继续使用原复杂成文模型。普通问答仍使用复杂模型。环境变量 `OVERVIEW_MODEL` 可覆盖，非法值启动失败。
- **保留上下文，前置定义**：从本篇所有已读正文抽取完整型号，将含型号的完整块前置，随后保留其余全部原文。没有型号保持原顺序。不切句、不丢背景或代词先行词、不改原观察、不跨篇抽取。早期四块裁为两块的方案已撤销。
- **动态约束**：系统提示要求逐字保留本篇完整型号，区分研究对象、对比对象、替代与版本继承，不能只列名称或以参数量替代；不硬编码论文或型号。
- **排版规范化**：仅把纯正文空白与换行合并为单段，不增删事实；列表/标题保持原样交给校验，不靠拼接掩盖提纲。
- **质量与预算**：最多三路主请求、每篇 600 输出 token、原有成文截止、校验后整体提交保持。不保留批量生成、自动纠正或备用模型切换；流错误/超时明确失败。另增加可关闭的绝对耗时竞速，见 §7；并发和调用统计必须包含额外候选。
- **慢阶段诊断**：按篇记录输入字节、可用/选中块数、首正文时间、最大正文增量间隔、总耗时、实际路由及错误；模型日志保留真实结束原因。取消成本状态记为 `cancelled`。
- **重复对照工具**：`benchmark_tail.py` 保留每次完整记录及哈希，不丢失败样本；同题、跳缓存、无客户端重试，要求运行有效且问题一致。报告均值、中位数、观测最大值，不从小样本推出总体 P95。可设置并记录轮间间隔，间隔测试不代表突发容量。

最终完整回归期间还观察到多道普通问答的复杂模型成文约 24–29 秒（模型客户端日志），而普通问答没有切换快层。因此长尾并非只来自多篇总览的并发等待，后续也要对普通成文采样；不把这组耗时误归于本轮概述路由。

名称覆盖不能证明关系正确。保留全文能避免主动删掉背景，但最终仍需人工或逐要点证据评分检查主题覆盖与事实归属。该路由只降低部分分支的复杂模型调用，复杂分支长尾仍然存在，不能宣称完全解决。

日志确认每题三篇中两篇用 `intern-s1-mini`，包含必保型号的篇目用 `intern-s2`；一次调用/篇，没有自动重试。抽查五次完整回答均包含三篇、预训练、完整型号及 2.0 继承关系，没有追加英文原文。关系精度仍需逐要点评分，尤其不能将模型本体与视觉编码器的评测贡献混同。

同版本完整回归 `20261102T094217200092Z_full.json` 为 **24/24**，全部完成、无流式错误、运行有效。但总览再次达到 **18,980 ms**，超过前面五次的最大值；不能只选择更好的定向样本。该结果触发后续绝对耗时竞速实验，并证明单靠路由尚未稳定压住尾部。

## 7. 绝对耗时触发的有界竞速候选

与早期空闲触发实验不同，本候选按每篇生成的**总耗时**触发，覆盖持续缓慢输出。配置 `chat.overview_hedge_after_ms` / `OVERVIEW_HEDGE_AFTER_MS`，默认 0（关闭），开发环境本次测试为 4000 ms。

- 每个完整总览最多一个额外候选；每个 Core 进程最多两个额外请求同时运行。预算或槽位不足直接等待主请求，不排队补发。
- 每个候选使用相同证据和选层，独立缓冲并完成同样的校验；先通过者作为结果，取消另一个，不拼接候选。两者均失败才返回错误；在触发前已失败不补发。
- 共享原截止和父取消；不把 35 秒放宽为两轮 35 秒。调用增加、取消和未获收益都须留证。客户端取消不保证上游停止计费。
- race 测试覆盖快速完成/早期错误不重复、持续慢请求触发、校验失败不能抢先、取消败者、单总览预算和进程槽位饱和。

对照记录 `20261102T094748653361Z_tail_benchmark.json`，两组都为五次、相同问题、无缓存/客户端重试、轮间 10 秒；服务端状态未锁定，仍不是因果隔离或 P95 验收。

| 指标 | 无竞速保守路由 | 4000 ms 竞速候选 |
| --- | ---: | ---: |
| 通过 | 5/5 | 5/5 |
| 平均耗时 | 7,815 ms | 5,070 ms |
| 中位数 | 8,229 ms | 3,688 ms |
| 观测最大值 | 11,923 ms | 10,251 ms |

候选镜像 `sha256:24f8ccc14b27567546708da0367314827fef74cc1e4afd4126cffc24a6c086aa`。五次共触发两次额外请求（17 次成文请求，相比基线 15 次增加约 13.3%）；从时间日志看两次均由原请求先完成，备份被取消。**这批样本没有证明备份抢救慢分支的收益，不能把整批变快归功于竞速。** 当前仅开发测试启用，生产默认关闭；需继续采集备份胜出率、节省时间、取消后实际 token 成本、限流率和并发容量后再决定是否推广。


最终候选完整回归：`20261102T095218100334Z_full.json`，冻结的 `upgrade_regression_v1` 为 **24/24**（SCP 可答 9/9、论文可答 10/10、拒答/隔离 5/5）；24 题均收到完成事件、流式错误 0、`run_valid=true`，源码/清单/本地镜像在运行中未变化。本轮总览 **2,578 ms**，未达到竞速触发时间。它与上一版本全量的 18,980 ms 都保留，不能用最新单次代替 P95 验收，也不能据此声称竞速已在真实慢请求中获益。不是原 S1 验收。

可追溯的阶段日志：`20261102T095218100334Z_core_metrics.log`（包含最终五次对照及本轮完整回归）。取消败者产生的 `context canceled` 与用户侧流错误分别统计。当前实现的线程安全客户端在显式启用策略时须支持三路主请求加最多一路额外候选；没有策略的旧流实现仍最多三路。
