# RRF（Reciprocal Rank Fusion，倒数排序融合）

RRF 是一种用于合并多个不同检索系统排名结果的算法。它不依赖各系统的具体打分，而是**仅根据文档在每个结果列表中的排名位置**来计算综合得分，从而生成一个统一的最终排序。

在 AI Agent 的记忆检索，特别是 RAG（检索增强生成）系统中，RRF 是连接**关键词搜索（如 BM25）**与**语义向量搜索**这两条检索通路的关键技术。

## 核心原理：基于排名的融合

RRF 的核心思想是：**一个文档如果在多个独立的检索结果中都排名靠前，那么它最终的相关性就应该越高**。

它的计算公式如下：

```text
RRF_score(d) = Σ 1 / (k + rank(d))
```

公式中各部分含义如下：

- **d**：被评分的文档。
- **rank(d)**：该文档在某个检索结果列表中的排名位置（从 1 开始）。
- **k**：一个平滑常数，默认值通常为 60。
- **Σ**：对该文档在所有检索结果列表中的得分进行累加。

### 关键参数 `k` 的作用

常数 `k` 主要有两个作用：

1. **防止头部文档分数过高**：避免排名第一的文档得分（`1 / 1 = 1`）远高于其他文档。
2. **给予尾部文档合理权重**：让排名靠后的文档也能获得一定贡献，不至于被完全忽略。

`k = 60` 是一个经过实践验证的经验值，能在突出高排名文档和保留尾部文档贡献之间取得平衡。

## 初始排名从哪里来

RRF 本身不负责生成初始排名，它只负责把多个初始排名列表融合起来。每一路检索器的初始排名通常遵循同一个流程：

```text
打分（Score） -> 排序（Sort） -> 截取前 K 个（Top-K）
```

也就是说，BM25 Top-K 和向量检索 Top-K 是由不同检索算法独立计算出来的，RRF 只接收它们各自的“名次序号”。

### BM25 排名：关键词检索

BM25 是一种基于词频（TF）和逆文档频率（IDF）的统计算法。它主要看字面匹配，不直接理解语义。

直观来看，BM25 的打分会受到以下因素影响：

- **词频加分**：文档中查询词出现次数越多，相关性分数通常越高。
- **稀有词加权**：越少见、越能区分文档的词，权重通常越高。
- **文档长度惩罚**：长文档天然更容易包含查询词，因此需要适度降权。

例如用户搜索 `Python 读取 CSV`，BM25 可能得到如下原始分数：

| 文档 | BM25 原始分 | 解释 |
| :--- | :--- | :--- |
| D1（`pandas.read_csv` 官方文档） | 18.5 | 标题和正文高频出现 `Python`、`read_csv`，文档较精炼，排名第 1。 |
| D3（Python CSV 模块教程） | 16.2 | 命中 `CSV` 和 `读取`，但综合匹配略弱，排名第 2。 |
| D2（NumPy 数组操作） | 3.1 | 包含 `Python`，但缺少 `CSV` 和 `读取` 等关键意图，排名靠后。 |

系统会按 BM25 原始分从高到低排序，再截取前 K 个结果。

### 向量排名：语义检索

向量检索通常使用余弦相似度、点积或向量距离来衡量查询与文档的语义接近程度。它不只看字面词语是否匹配，更关注语义空间中的接近程度。

典型流程如下：

1. **离线阶段**：将文档通过 Embedding 模型转成向量，并存入向量数据库。
2. **在线查询**：将用户问题也转成查询向量。
3. **相似度计算**：计算查询向量与候选文档向量的相似度。
4. **排序截断**：按相似度降序排序，取 Top-K。

例如用户搜索 `如何用 Python 读取 CSV 文件？`，向量检索可能得到如下原始分数：

| 文档 | 余弦相似度 | 解释 |
| :--- | :--- | :--- |
| D3（Python CSV 模块教程） | 0.92 | 语义上最接近“如何读取 CSV 文件”的操作指南，排名第 1。 |
| D1（`pandas.read_csv` 官方文档） | 0.89 | 同样讲 CSV 读取，语义高度相关，排名第 2。 |
| D4（处理大文件的技巧） | 0.78 | 与“文件处理”相关，但不一定直接回答 CSV 读取，排名第 3。 |
| D5（数据科学入门指南） | 0.65 | 与数据处理相关，但意图匹配较弱，排名靠后。 |

在百万级文档规模下，向量数据库通常不会对所有向量逐一精确计算，而是先使用 ANN（Approximate Nearest Neighbor，近似最近邻搜索）快速缩小候选范围，再对候选集精排。常见 ANN 索引包括 HNSW 和 IVF。

如果查询包含过滤条件，例如“只看 2025 年的文档”，系统还会先根据元数据做过滤前置（Pre-filtering），再对过滤后的候选文档进行打分排序。

### 为什么原始分数不能直接相加

BM25 分数和向量相似度的量纲不同，不能直接比较：

- BM25 分数可能是 `18.5`、`16.2`、`3.1`，没有统一上限。
- 向量余弦相似度通常在 `0` 到 `1` 之间，例如 `0.92`、`0.89`、`0.65`。

如果直接把两者相加，BM25 的数值范围可能完全淹没向量分数，导致语义检索失效。RRF 放弃这些不可比的原始分数，只使用排名序号 `1`、`2`、`3` 等进行融合，从而规避分数量纲不统一的问题。

## 为什么在 AI Agent 中重要

在 AI Agent 的记忆检索中，RRF 之所以被广泛采用，主要因为它解决了传统融合方法的三大痛点。

### 1. 无需分数归一化（No Score Normalization）

**问题**：不同检索系统的打分机制和量纲完全不同。例如，BM25 的相关性分数可能高达几十，而向量相似度分数通常在 0 到 1 之间。直接相加或加权会严重偏向某一方。

**RRF 的解决方式**：完全忽略原始分数，只使用统一的“排名”这一度量，从根本上规避复杂的分数标准化问题。

### 2. 无需繁琐调参（Tuning-Free）

**问题**：传统的线性加权融合（如 `最终得分 = α × 向量分 + β × BM25 分`）需要花费大量精力去调整超参数 `α` 和 `β`，且这些参数在不同数据集上效果差异很大。

**RRF 的解决方式**：它是一种**非参数化（Non-parametric）**方法，开箱即用，几乎无需调整。

### 3. 公平融合（Fair Fusion）

**问题**：如果某个检索器打出的分数普遍偏高，在分数融合中就会占据主导地位。

**RRF 的解决方式**：RRF 对每个检索源都“一视同仁”，最终排名由文档在所有列表中的**综合排名表现**决定，而非某个系统的绝对分数。

## 典型应用场景

在 AI Agent 和更广泛的搜索系统中，RRF 主要应用于以下场景：

| 应用场景 | 描述 |
| :--- | :--- |
| **混合检索（Hybrid Search）** | 同时执行基于关键词的全文检索和基于向量的语义检索，然后用 RRF 融合两者的结果。 |
| **多路召回融合** | 在推荐系统或知识库中，合并来自不同召回通路（如协同过滤、内容召回等）的结果。 |
| **多查询检索** | 将一个用户问题改写为多个不同表述，分别检索后再用 RRF 融合，以提高召回率。 |
| **多字段查询** | 对文档的标题、正文、标签等多个字段分别进行检索，然后融合排序。 |

## 示例一：混合检索融合

假设用户提问：

```text
如何用 Python 读取 CSV 文件？
```

系统同时使用 BM25 和向量检索，每种检索方式都返回 Top 5 结果。

### BM25 检索结果

| 排名 | 文档 ID | 文档标题 |
| :--- | :--- | :--- |
| 1 | D1 | `pandas.read_csv` 官方文档 |
| 2 | D3 | Python CSV 模块教程 |
| 3 | D5 | 数据科学入门指南 |
| 4 | D2 | NumPy 数组操作 |
| 5 | D7 | Python 异常处理 |

### 向量检索结果

| 排名 | 文档 ID | 文档标题 |
| :--- | :--- | :--- |
| 1 | D3 | Python CSV 模块教程 |
| 2 | D1 | `pandas.read_csv` 官方文档 |
| 3 | D4 | 处理大文件的技巧 |
| 4 | D9 | Python 文件 I/O 基础 |
| 5 | D5 | 数据科学入门指南 |

### 计算过程

使用 `k = 60`，每个文档在某个列表中的贡献为：

```text
1 / (60 + rank)
```

以 D1、D3、D5 为例：

| 文档 ID | BM25 贡献 | 向量贡献 | RRF 总分 |
| :--- | :--- | :--- | :--- |
| D1 | `1 / (60 + 1) ≈ 0.01639` | `1 / (60 + 2) ≈ 0.01613` | `0.03252` |
| D3 | `1 / (60 + 2) ≈ 0.01613` | `1 / (60 + 1) ≈ 0.01639` | `0.03252` |
| D5 | `1 / (60 + 3) ≈ 0.01587` | `1 / (60 + 5) ≈ 0.01538` | `0.03126` |

完整融合结果如下：

| 最终排名 | 文档 ID | BM25 排名 | 向量排名 | RRF 得分 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | D1 | 1 | 2 | 0.03252 |
| 2 | D3 | 2 | 1 | 0.03252 |
| 3 | D5 | 3 | 5 | 0.03126 |
| 4 | D4 | 未上榜 | 3 | 0.01587 |
| 5 | D2 | 4 | 未上榜 | 0.01562 |
| 6 | D9 | 未上榜 | 4 | 0.01562 |
| 7 | D7 | 5 | 未上榜 | 0.01538 |

关键结论：

- D1 和 D3 在两个榜单中都位列前茅，因此总分最高，稳定排在前面。
- D5 在两个榜单中都出现，虽然不是第一，但综合表现稳定，因此排在只命中单路检索的文档之前。
- D4 只在向量检索中排名第 3，仍能获得合理位置，但缺少 BM25 的共同支持。
- D2、D7、D9 只出现在单一路径中，因此总分相对较低。

这能避免某个检索源的单一偏好，让多个检索器共同认可的“共识文档”优先出现。

## 示例二：多查询改写融合

假设用户问题表述较模糊：

```text
那个很火的 AI 框架怎么装？
```

系统可以将问题改写成多种表述，并分别检索：

| 检索查询 | 排名 1 | 排名 2 | 排名 3 |
| :--- | :--- | :--- | :--- |
| 查询 A：`PyTorch 安装教程` | D1 | D5 | D3 |
| 查询 B：`深度学习框架 环境配置` | D5 | D1 | D2 |
| 查询 C：`AI 库 pip 安装` | D3 | D1 | D5 |

使用 RRF 融合后：

| 文档 ID | 查询 A 排名 | 查询 B 排名 | 查询 C 排名 | RRF 得分 | 最终排名 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| D1 | 1 | 2 | 2 | `1/61 + 1/62 + 1/62 ≈ 0.04865` | 1 |
| D5 | 2 | 1 | 3 | `1/62 + 1/61 + 1/63 ≈ 0.04840` | 2 |
| D3 | 3 | 未上榜 | 1 | `1/63 + 0 + 1/61 ≈ 0.03227` | 3 |
| D2 | 未上榜 | 3 | 未上榜 | `0 + 1/63 + 0 ≈ 0.01587` | 4 |

D1 和 D5 在三次检索中都稳定出现且排名靠前，因此 RRF 会自然将它们推到最前面。

## 伪代码实现

```python
def reciprocal_rank_fusion(result_lists, k=60):
    """
    融合多个检索结果列表。

    Args:
        result_lists: list[list[str]]，每个子列表是按相关性降序排列的文档 ID。
        k: 平滑常数，默认 60。

    Returns:
        list[tuple[str, float]]，按 RRF 得分降序排列的文档列表。
    """
    scores = {}

    for rank_list in result_lists:
        for rank, doc_id in enumerate(rank_list, start=1):
            scores.setdefault(doc_id, 0.0)
            scores[doc_id] += 1.0 / (k + rank)

    return sorted(scores.items(), key=lambda item: item[1], reverse=True)


bm25_results = ["D1", "D3", "D5", "D2", "D7"]
vector_results = ["D3", "D1", "D4", "D9", "D5"]

final_ranking = reciprocal_rank_fusion([bm25_results, vector_results])
print(final_ranking)
```

输出结果类似：

```text
[
    ('D1', 0.03252),
    ('D3', 0.03252),
    ('D5', 0.03126),
    ('D4', 0.01587),
    ...
]
```

## 常见陷阱与检查

| 陷阱 | 说明 | 检查方法 |
| :--- | :--- | :--- |
| **排名从 0 开始** | 如果代码里 `rank` 从 0 开始，需要使用 `1 / (k + rank + 1)`，否则排名第一的文档会得到 `1 / 60` 而不是 `1 / 61`。 | 验证单文档、单列表时，总分应约等于 `1 / 61`。 |
| **结果列表长度不一致** | RRF 不需要分数归一化，但较长列表会让更多尾部文档获得出现机会。 | 可统一截断到固定长度，例如 Top 20 或 Top 50。 |
| **重复文档未去重** | 同一个检索器结果列表中如果出现重复文档，会导致该文档被重复加分。 | 每个检索器内部先按文档 ID 去重，再参与融合。 |
| **并列分数未处理** | 多个文档可能得到完全相同或非常接近的 RRF 分数。 | 增加稳定排序规则，例如优先保留主检索器排名、更新时间或业务权重。 |
| **盲目调整 `k`** | 默认 `k = 60` 通常够用。过小会过度强调头部排名，过大则会削弱头部优势。 | 通过离线评测或 A/B 测试比较 `k = 10`、`60`、`100` 等配置。 |

## 局限性与方法对比

尽管优势明显，RRF 也有其局限性：

- **信息损失**：完全丢弃原始分数信息，而这些分数本身可能包含有价值的置信度信息。
- **权重表达有限**：标准 RRF 默认平等对待每个检索源，如果业务上需要明显偏向某个检索器，需要引入加权 RRF 或后置重排。
- **性能考量**：虽然计算简单，但在多路召回、长列表融合时，仍需要控制每路 Top-K 的长度和去重策略。

与其他融合方法的对比如下：

| 融合方法 | 核心逻辑 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- |
| **RRF** | 基于排名位置计算倒数得分 | 无需调参、无需归一化、公平融合 | 丢弃原始分数信息 |
| **线性加权（Linear Weighted）** | `α × 分数1 + β × 分数2` | 可灵活调节权重 | 需要大量调参，分数归一化困难 |
| **CombSUM** | 直接加和归一化后的分数 | 实现简单 | 依赖分数归一化效果，不同系统间分数难对齐 |

## 总结

RRF 是一种“化繁为简”的融合方法。它通过**忽略不可比的分数，只关注统一的排名**，解决多检索系统融合中的核心难题。

一句话概括：

- **BM25 的 Top-K** 来自关键词命中、词频、稀有词权重和文档长度等统计特征。
- **向量检索的 Top-K** 来自语义向量之间的相似度排序。
- **RRF 的最终排序** 来自多个检索结果列表中的排名序号融合，而不是原始分数相加。

在构建 AI Agent 的记忆检索模块时，RRF 是实现**混合检索（Hybrid Search）**、平衡**关键词的精确性**与**语义的泛化性**的关键技术，能有效提升最终给到 LLM 的上下文质量。
