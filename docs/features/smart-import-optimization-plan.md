# 智能导入最终优化方案

> **文档类型：设计方案与计划。** 正文含设计目标或待办，实际交付以架构、接口文档和代码为准。 [当前文档入口](../README.md)

> 基于现有实现与三轮评审，从去重防污染、LLM输出校验、缓存质量、信息密度模型、拆分鲁棒性、噪声过滤、置信度可解释性、多模态校验、导入后治理九个维度形成最终方案。  
> **核心目标**：最终入库的知识零污染、零噪声，且不依赖任何粗略关键词匹配或 Markdown 格式残留。

---

## 0. 核心设计原则

1. **零噪声知识**：入库文本为纯自然语言，不含 Markdown、HTML、URL、代码块等格式杂质。
2. **智能判别代替关键词匹配**：使用结构信号、信息密度、LLM 语义判别及实体归一化，杜绝字面噪声过滤。
3. **多层防御**：每段知识须通过**信息密度检测 → LLM 噪声清洗 → 实体校验 → 门禁规则**四道关卡。
4. **实体归一化贯穿始终**：Embedding 去重、标题校验、标签生成均以实体归一化为锚点，避免短文本语义漂移。
5. **全生命周期治理**：导入前预防、导入中拦截、导入后反馈淘汰形成闭环。

## 一、语义去重（紧急 · 三层架构）

### 1.1 三层去重逻辑
```
层1：精确 Hash  → content_hash 相同 → Unchanged
层2：实体归一化匹配 → 同 subject（别名归一化后） + 标题编辑距离≤3 或 LCS占比≥0.70 → 候选重复
层3：Embedding 语义 → 仅在前两层无法判断时启用，且必须满足「同主实体 + cosine≥动态阈值」才判重
```

**联合规则**：同主实体（经别名归一化）AND 向量 cosine ≥ 阈值，才算重复；实体不同则即使向量相似度高也放行（如「InternVL 教程」与「InternVL 论文」）。

### 1.2 动态阈值
| 文档类型 | 拒绝阈值 | 警告阈值 |
|----------|----------|----------|
| 单体文档 | 0.80 | 0.65 |
| 综合合集 | 0.85 | 0.70 |
| 问答集   | 0.82 | 0.68 |
| 多模态合并 | 0.85 | 0.70 |

- 相似度 ≥ 拒绝阈值 **且** 主实体相同 → 拒绝入库，返回已有文档信息。
- 警告阈值 ≤ 相似度 < 拒绝阈值 → 前端展示 warning，仍可提交。

### 1.3 批量导入内部去重
- 对批次内所有 segment 计算 **MinHash 签名**（128哈希函数），通过 **LSH 桶** 召回相似度 ≥0.90 的候选对。
- 仅对候选对做精确 cosine 计算，聚簇合并，保留信息最丰富的正文。

### 1.4 更新场景实体感知降权
- `target_doc_id` 更新时，被比较文档的 `subject` 与当前不同 → 相似度 × 0.7。
- 降权后 ≥ 0.90 → warning；< 0.90 → 放行，避免系列文档误判。

### 1.5 实体缺失降级
- 若未能提取高置信度主实体，退化为全维度 Embedding 相似度，阈值提升至 0.92，防止漏去重。

## 二、LLM 输出校验强化（紧急）

### 2.1 标题多条件校验（满足任一即可）
1. 子串匹配（快速路径）
2. Levenshtein 编辑距离 ≤ 3
3. 最长公共子序列 (LCS) 占比 ≥ 0.70（短标题防误杀）

### 2.2 Entities 三步逐级校验（避免 Embedding 单独判定短实体）
1. **别名库命中**：`taxonomyevolve` 实体别名库直接映射（最快）
2. **直接匹配**：实体名在原文中出现
3. **Embedding 兜底**：仅在前两步未命中时启用，且必须在工作区实体白名单约束内
   未通过三步且不在白名单的实体 → 降级为 `generic` 或丢弃。

### 2.3 字段分级修复
JSON 解析失败时：
- **核心字段** (`title`, `summary`)：正则提取并修复
- **结构字段** (`logic_skeleton`, `range`)：必须完整解析，绝不可局部修复，失败则回退规则拆分

### 2.4 KB Type 白名单
- 仅接受工作区预定义的精确 `gd_*` 列表，任何非法值均用 `hint_kb_type` 覆盖并记录日志。

## 三、多模态缓存质量治理（紧急）

### 3.1 多维度质量评分
任一维度不及格则 `quality_score = 0`，强制不走缓存。

| 维度 | 指标 | 判零条件 |
|------|------|----------|
| `format_score` | 表格完整性 + 换行正常度 | < 0.3 → 0 |
| `language_score` | N-gram 重复率 | > 0.5 → 0（OCR 错误循环信号） |
|                | 语言模型困惑度（小模型） | > 阈值 → 0 |
| `entity_density` | 有效实体数 / 总词数 | < 0.03 → 0 |

`quality_score = format×0.3 + language×0.35 + entity×0.35`
- < 0.3 → `verified=false`，触发重提取
- ≥ 0.6 → `verified=true`，直接复用

### 3.2 pHash 三级复核（避免高成本 CLIP 直接调用）
1. 颜色直方图相似度 ≥ 0.90 → 通过
2. 不确定时 (0.80-0.90) → SSIM 复核
3. 仍不确定 → CLIP cosine ≥ 0.95 最终确认
   仅在最后一步启用 CLIP，平衡性能与准确率。

### 3.3 低质量缓存回收
- 定时扫描 `quality_score < 0.4` → 异步重提取
- 重提不达标 → `quarantined=true`，人工或模型升级后重新处理

## 四、信息密度模型（代替实体密度，避免误杀高信息文本）

### 4.1 多维信息密度计算
```
信息密度 = Σ(各维度得分) / 总词数
维度得分：
- 实体词（人名、地名、专有名词）：+1.0
- 动作动词（闪避、释放、触发等）：+0.8
- 数字+单位（3秒、150%）：+0.6
- 领域术语（暴击、充能等）：+0.7
- 步骤标记（第一步、然后）：+0.5
```

| 文本示例 | 传统实体密度 | 多维信息密度 |
|----------|--------------|--------------|
| 「闪避敌人技能后立刻接重击」 | 0 | ≈0.24 |
| 「界面包含按钮、文字：确定」 | 0 | ≈0.05 |
| 「步骤1：准备材料；步骤2：合成」 | 0 | ≈0.18 |

### 4.2 意图模式反诈（防止营销噪声伪装高密度）
构建轻量解析器识别**营销模式模板**：
- 价格模式：`[数字]+元+[皮肤/道具]`
- 时间压力：`限时、截止、最后X天`
- 号召动作：`点击下载、充值返利`
  命中任一模板 → 标记“疑似营销”，**与信息密度无关**，直接强制清洗或拒绝。

### 4.3 动态词表与自适应阈值
- 从现有知识库用 TF-IDF 每周提取领域高频词，自动扩充术语表。
- 定期抽样计算已入库知识的信息密度分布，动态调整“噪声/有效”分界线。

## 五、Markdown 剥离与结构化知识保存

### 5.1 剥离时机后移
```
Raw Text (保留 Markdown) 
→ ScanSkeleton → Unified LLM → PlanSegments → Analyze (全部依赖结构)
→ 入库前 CleanMarkdownForIngest → 纯自然语言存储
```

### 5.2 表格语义转述（不保留任何 MD 语法）
表格块在剥离前转换为自然语句：
- 属性-值表转为：“InternVL 推荐使用视觉编码器，推理参数选择推理参数”。
- 列表转为连贯描述：“包括 A、B 和 C”；有序列表转为“第一步是…第二步是…”。
  仅当信息密度高时触发轻量 LLM 或模板转述，避免碎片化。

## 六、置信度模型：规则标签三档（替代伪精确连续值）

| 检查项 | 通过条件 |
|--------|----------|
| 结构完整 | 骨架标题数 ≥ 1 |
| 实体通过 | 信息密度 ≥ 0.06 |
| 噪声低 | N-gram 重复率 ≤ 0.5 |
| 标题可信 | 通过子串/编辑距离/LCS 校验 |
| 实体可溯源 | ≥50% entities 通过白名单或原文匹配 |

| 档位 | 条件 | 行为 |
|------|------|------|
| **Pass** | 全部 ✓ | 可提交 |
| **Warning** | 1-2 项 ✗（非“实体通过”和“噪声低”） | 前端警告，仍可提交 |
| **Reject** | “实体通过”或“噪声低” ✗，或 ≥3 项 ✗ | 拒绝入库 |

**短知识豁免**：字数 < 80 且含 ≥1 专有名词，若“标题可信”和“实体可溯源”均通过，则无论信息密度多少，降级为 Warning 允许提交。

## 七、拆分鲁棒性（保证语义单元完整）

### 7.1 无结构长文兜底
- 正文 > 5000 字且无标题/分隔符 → 基于句子边界分块，每块 800-2000 字。
- 轻量 LLM 判断是否语义独立，避免生成无意义碎片。

### 7.2 智能短段合并（避免 Pairwise 向量成本）
- 短段与前后段计算**关键词 Jaccard 重叠率**作为快速信号。
- 重叠率高侧合并；两侧均低则独立保留。
- 仅当重叠率差值 < 0.1 时，才启用向量相似度精确判断合并方向。

---

## 八、噪声过滤智能化（按需触发，控制成本）

### 8.1 信息密度过滤（第一道）
密度 < 0.06 → 直接拒绝，不浪费后续资源。

### 8.2 LLM 清洗触发策略
| 信息密度范围 | 动作 |
|--------------|------|
| < 0.06 | 拒绝 |
| 0.06 – 0.10 | 轻量 LLM 语义清洗 |
| > 0.10 | 跳过清洗，仅 Markdown 剥离 + 文本标准化 |
| 含疑似营销信号 | 即使 > 0.10 也强制清洗 |

### 8.3 清洗约束协议（防止二次噪声）
- LLM 清洗时**仅允许删除非知识性句子**，禁止改写专有名词、数字、动词。
- 输出后**事实一致性校验**：清洗后文本中的所有专名和数字必须在原文本中出现，否则回退到未清洗版本。

### 8.4 通用文本标准化（入库前最后一步）
- HTML 实体解码、URL 移除、代码块移除
- 全角转半角、零宽/控制字符清除
- 连续空行归一化

---

## 九、多模态事实校验（防止 VLM 幻觉污染）

### 9.1 提取实体白名单校验
- 图片/视频提取文本中的专有名词，在知识库实体白名单中进行存在性检查。
- 出现未知实体名 → 标记 `multimodal_uncertain=true`，降低段落置信度，入库为 `draft`。

### 9.2 跨模态一致性投票
- 若同时存在用户 `raw_text`，比较其专有名词集合与多模态提取的实体集合。
- 无交集且多模态实体不在原文提及范围 → 判为幻觉，移除该实体。

## 十、导入后知识质量反馈闭环（长期最重要）

### 10.1 knowledge_score 模型
| 信号 | 来源 | 权重 |
|------|------|------|
| 检索命中次数 | 检索日志 | 0.20 |
| 被引用次数 | Chat 引用统计 | 0.25 |
| 用户正向反馈 | 点赞/采纳 | 0.30 |
| 用户负向反馈 | 点踩/忽略 | -0.15 |
| 内容时效衰减 | 按 doc_type 半衰期 | 0.10 |

### 10.2 自动降权与淘汰（含冷门保护）
- `knowledge_score < 0.2` 持续 30 天 → 自动降权
- `knowledge_score < 0.1` 持续 60 天 → `deprecated`
- **冷门保护**：若淘汰会导致某实体下知识文档数归零，则冻结淘汰，仅降低检索排名。

### 10.3 来源追踪与统计
- 所有 smart-import 文档标注 `source=smart_import` 及 `source_type`。
- 按来源统计导入时的信息密度 vs 后续 knowledge_score，持续调优导入参数。

## 十一、辅助强化措施

### 11.1 缓存清理精细化
- 精准失效：清除含新文档关键实体/标题词的缓存键。
- 延迟全量：5 分钟内不重复触发全量刷新。

### 11.2 Worker 门禁增强（组合条件替代硬字数限制）
1. 字数 < 80 且信息密度 < 0.06 且无可溯源实体 → 拒绝
2. 字数 80-150 但含已知实体且标题可信 → 降级 `draft`，等待审核
3. 敏感词检测、重复字符 > 40%、纯 URL → 拒绝
